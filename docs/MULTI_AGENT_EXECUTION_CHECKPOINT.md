# Multi-Agent Asynchronous Execution & Failover Checkpoint Tracker

This file tracks the atomic completion state and `conversationId` of the 5-step real engineering upgrade across 6 agents (1 Orchestrator + 5 Asynchronous Specialist Subagents defined in `.agents/agents/*.md`).

### Asynchronous Subagent Rules (`https://antigravity.google/docs/subagents#asynchronous-subagents`)
1. **Parallel Non-Blocking Launch**: All subagents within a wave are spawned concurrently in a single turn via `invoke_subagent` with `Workspace: "inherit"` and `Model: "inherit"`, starting with isolated context windows to save tokens.
2. **Zero-Polling Reactive Wakeup**: After spawning a wave, the Orchestrator immediately ends its turn and waits for Antigravity's reactive auto-wake notification.
3. **`Idle` State & Instant Revival (`send_message`)**: If a subagent pauses due to a server restart or token limit, its full context remains preserved under its `conversationId`. Send a message to its `conversationId` via `send_message` (or switch the UI model dropdown to **Gemini 3.8 Flash (High)** and spawn/revive the agent) to resume from the exact unfinished substep below.
